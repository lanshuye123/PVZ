# 04 · 存档配置（`savedata.ini`）

> 本功能由本仓库新增，上游 `InLiothixi/stabledecompile` 没有。
> 技术实现与回退方式见 [变更记录 03 · 可配置的存档位置](changes/2026-10-07-03-configurable-save-data.md)。

## 为什么需要它

原版（以及上游工程）把存档**固定在** `%PROGRAMDATA%\PopCap Games\PlantsVsZombies\`，
也就是"全机器共享"的位置。这带来几个问题：

- 多用户共用一台机器时，存档互相覆盖（`ProgramData` 是共享目录）
- 装在 Program Files 的绿色版/便携版无法把存档带在 U 盘上
- 多个独立的 mod 实例无法各用一套存档
- 服务器 / 受限账户下 `ProgramData` 可能不可写

现在改成由**随游戏分发的静态配置文件**决定，风格参考《Minecraft》。

## 配置文件在哪

```
<游戏目录>\savedata.ini
```

- **源码位置**：`assets\savedata.ini`
- 构建时由 PostBuildEvent 的 `robocopy assets → bin` **自动复制到 exe 旁边**，
  所以它天然"随程序分发"。
- 如果文件不存在，游戏使用默认模式，**不会报错**。

## 格式

极简 INI：

```ini
# 以 # 或 ; 开头的是注释
mode = user

# [section] 会被忽略（允许存在，但不解析）
path = D:\PvZSaves
```

解析规则：

- `键 = 值`，键名**大小写不敏感**（`Mode` / `MODE` 都可以）
- 允许键值两侧有空白
- 注释只在**前面是空白**时才算注释，所以路径里可以安全出现 `#` 和 `;`
  （例如 `path = D:\my#saves`）
- 支持 UTF-8 BOM（用记事本另存为 UTF-8 不会出问题）
- **未知键会被忽略**，可以放心加自己的备注

## 五种模式

| `mode` | 存档根目录 | 典型用途 |
|---|---|---|
| `user` **（默认）** | `%APPDATA%\PopCap Games\PlantsVsZombies` | 普通桌面安装。按用户隔离，随 Windows 用户配置漫游 |
| `portable` | **exe 所在目录** | 绿色便携版：解压即用，整个文件夹拷走存档跟着走 |
| `instance` | **进程启动时的工作目录** | 一套启动目录一套存档。多个快捷方式设不同"起始位置"，或启动器指定 cwd |
| `static` | 配置里 `path` 指定的路径 | 存档放指定位置（如第二块硬盘、同步盘） |
| `legacy` | `%PROGRAMDATA%\PopCap Games\PlantsVsZombies` | 保留原行为，兼容老安装 |

**未知或缺失的 `mode` 一律回退到 `user`**，所以删掉配置文件也不会出问题。

### 实际落盘位置

存档始终位于所选根目录下的 **`userdata\`** 子目录（沿用游戏原有结构），
模式只决定"根"：

```
user      → %APPDATA%\PopCap Games\PlantsVsZombies\userdata\users.dat
portable  → <游戏目录>\userdata\users.dat
instance  → <启动目录>\userdata\users.dat
static    → D:\PvZSaves\userdata\users.dat
legacy    → %PROGRAMDATA%\PopCap Games\PlantsVsZombies\userdata\users.dat
```

### 启动时会自动建目录

游戏启动时会主动创建所选**根目录**和它的 `userdata\` 子目录。
好处是：**你不用进游戏就能看出这个 build 到底往哪写**。

因此验证配置是否生效，最简单的办法就是启动一次游戏，然后看目录有没有出现：

```powershell
# 例如验证 portable 模式
Test-Path .\build\ReleaseGOTY_x64\bin\userdata
```

## 用法示例

### 例 1：默认（按用户）

```ini
mode = user
```

### 例 2：绿色便携版

```ini
mode = portable
```

把 `build\ReleaseGOTY_x64\bin\` 整个拷到 U 盘，存档就在同一个目录下的
`userdata\`，换机器也能继续玩。

### 例 3：多实例（一个启动目录一套存档）

```ini
mode = instance
```

然后建两个快捷方式，只改"起始位置"：

| 快捷方式 | 起始位置 | 存档 |
|---|---|---|
| PvZ 原版体验 | `D:\PvZ\vanilla` | `D:\PvZ\vanilla\userdata\` |
| PvZ 改版 | `D:\PvZ\modded` | `D:\PvZ\modded\userdata\` |

也可以用启动器：

```powershell
Start-Process "D:\PvZ\bin\PlantsVsZombies.exe" -WorkingDirectory "D:\PvZ\instances\survival"
```

> **注意**：从资源管理器里双击 exe 时，工作目录就是 exe 所在目录，
> 所以此时 `instance` 与 `portable` 效果相同。要让两者产生差异，
> 必须显式指定不同的启动目录。

### 例 4：固定路径

```ini
mode = static
path = D:\PvZSaves
```

实际写入 `D:\PvZSaves\userdata\`。

- 绝对路径直接用；
- **相对路径**（如 `path = saves`）会相对 **exe 所在目录** 解析 → `<游戏目录>\saves\userdata\`；
- `mode = static` 但 `path` 为空 → 回退到 `user`（不会写到一个空的相对路径里）。

### 例 5：沿用老位置

```ini
mode = legacy
```

## 从旧存档迁移

如果之前已经有存档在 `%PROGRAMDATA%\PopCap Games\PlantsVsZombies\userdata\`：

**办法 A（推荐，零风险）**：直接把 `mode` 设成 `legacy`，游戏继续用老位置。

**办法 B**：把老 `userdata\` 目录里的文件**复制**到新位置的 `userdata\` 里。
先启动一次游戏让新目录被创建，再复制：

```powershell
$old = "$env:ProgramData\PopCap Games\PlantsVsZombies\userdata"
$new = "$env:APPDATA\PopCap Games\PlantsVsZombies\userdata"   # 若用默认 user 模式
New-Item -ItemType Directory -Force -Path $new | Out-Null
Copy-Item "$old\*" $new -Force
```

> 游戏**不会**自动迁移，也不会删除任何旧存档。两种办法都不会丢数据。

## 常见问题

**改了配置没生效？**

1. 确认改的是**正在运行的那个 exe 旁边**的 `savedata.ini`
   （不是 `assets\` 里那份，也不是另一个配置的输出目录）。
2. 确认语法是 `mode = xxx`（有等号）。
3. 启动一次游戏，看新位置的 `userdata\` 是否出现。

**重新编译后配置被改回去了？**

PostBuildEvent 会用 `assets\` 覆盖输出目录，所以**输出目录里的
`savedata.ini` 会被 `assets\savedata.ini` 重置**。

- 要长期生效 → 改 **`assets\savedata.ini`**（源）
- 只是临时试 → 改输出目录那份，但别再重新编译

**游戏能起来但存档不保存？**

先确认 `userdata\` 目录真的被创建了。如果**目录根本没出现**，那多半不是本配置的问题，
而是进程没有写权限 —— 例如可执行文件被打了"低完整性"标签，导致它无法写入
`%APPDATA%` / `%ProgramData%` 这类正常位置。判断与处理见
[05-故障排查 · 存档无法保存](05-故障排查.md#症状存档完全无法固化每次启动都是全新的)。

**可以把 `path` 直接指向 `userdata` 本身吗？**

不可以。`path` 是**根目录**，游戏会在它下面再建 `userdata\`。
如果你想要"存档就在 `D:\PvZSaves` 里面"，就写 `path = D:\PvZSaves`，
文件会落在 `D:\PvZSaves\userdata\`（与其它四种模式保持一致）。

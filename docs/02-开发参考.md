# 02 · 开发参考

面向要修改本工程代码的人。所有结论以当前代码为准，标注 **（已验证）** 的项经过实测。

## 1. 构建配置矩阵

解决方案有 8 个配置（`Configuration × Platform`）：

| Configuration | Platform | 对应版本 | CRT | 预处理器补充 |
|---|---|---|---|---|
| `Debug` | Win32 | OG (2009) | 未显式设置 | `_WIN32;WIN32;_CRT_SECURE_NO_WARNINGS;_DEBUG` |
| `Debug` | x64 | **实际是 GOTY** ⚠️ | 未显式设置 | `_WIN64;WIN64;_GOTY;GOTY` |
| `DebugGOTY` | Win32 | GOTY | `MultiThreadedDebugDLL` (/MDd) | `_WIN32;WIN32;_CRT_SECURE_NO_WARNINGS;_DEBUG;_GOTY;GOTY` |
| `DebugGOTY` | x64 | GOTY | `MultiThreadedDebugDLL` (/MDd) | `_WIN64;WIN64;_GOTY;GOTY` |
| `Release` | Win32 | OG (2009) | `MultiThreaded` (/MT) | `_WIN32;WIN32;NDEBUG` |
| `Release` | x64 | **实际是 GOTY** ⚠️ | `MultiThreaded` (/MT) | `_WIN64;WIN64;NDEBUG;_GOTY;GOTY` |
| `ReleaseGOTY` | Win32 | GOTY | `MultiThreaded` (/MT) | `_WIN32;WIN32;NDEBUG;_GOTY;GOTY` |
| `ReleaseGOTY` | x64 | GOTY | `MultiThreaded` (/MT) | `_WIN64;WIN64;NDEBUG;_GOTY;GOTY` |

所有配置共有的定义：
`_LIB;_WINDOWS;_VISUALC_;_JPEGLIB_;OPTIMIZE_SOFTWARE_DRAWING;DO_FIX_BUGS;_ENABLE_DRM_FOR__DEBUGGING`

### ⚠️ 陷阱一：所有 x64 配置都会定义 `_GOTY`

`SexyAppBase.vcxproj` 里四个 x64 配置的 `PreprocessorDefinitions` 都带 `_GOTY;GOTY`，
**包括名字里没有 GOTY 的 `Debug|x64` 和 `Release|x64`**。而 Win32 配置是正确区分的。

后果：在 x64 上你**无法**构建出真正的 OG(2009) 版本 —— 即使选 `Release|x64`，
`GameConstants.h` 里的 `#ifdef _GOTY` 分支依然会打开成就、Zombatar 等内容。
要用 OG 版本请选 **Win32** 配置，或自行修正 x64 配置的定义。

### ⚠️ 陷阱二：Release 配置使用 EditAndContinue 调试格式

四个 Release 配置都设了 `<DebugInformationFormat>EditAndContinue</DebugInformationFormat>`
（即 `/ZI`）。这是从 VS2005 项目升级时残留的，通常只该用于 Debug。
它会让 Release 二进制带上可编辑调试信息，体积偏大。

### 编译选项

每个 `ClCompile` 配置都带：

```xml
<AdditionalOptions>/source-charset:utf-8 /wd4996 %(AdditionalOptions)</AdditionalOptions>
<LanguageStandard>stdcpp20</LanguageStandard>
```

`/source-charset:utf-8` 是必需的，原因见 [第 6 节](#6-源文件编码约定)。

## 2. 渲染与分辨率

### 初始化路径

`LawnApp::Init()`（`LawnApp.cpp` 约 345 行起）：

```cpp
mWidth  = BOARD_WIDTH;    // 800   ← 构造函数设置
mHeight = BOARD_HEIGHT;   // 600
// Init() 里曾有 #define _WIDE_SCREEN 把它改成 1066x600（本仓库已注释掉）

mSDLWindow   = SDL_CreateWindow(mTitle.c_str(), mWidth, mHeight, windowFlags);
mSDLRenderer = SDL_CreateRenderer(mSDLWindow, nullptr);
SDL_SetRenderLogicalPresentation(mSDLRenderer, mWidth, mHeight,
                                 SDL_LOGICAL_PRESENTATION_LETTERBOX);

mWidgetManager->mImage->mD3DData =
    SDL_CreateTexture(mSDLRenderer, SDL_PIXELFORMAT_ARGB8888,
                      SDL_TEXTUREACCESS_TARGET, mWidth, mHeight);
```

要点：

- 游戏按 **逻辑分辨率 800×600** 绘制到一个离屏纹理，再由 SDL 以
  `LETTERBOX` 方式缩放到窗口 —— 所以窗口拉伸不会改变游戏内部坐标。
- `mWidth` / `mHeight` 是**全局设计尺寸**，几乎所有界面硬编码坐标都基于它。
  改这两个值会牵动所有以 800×600 排版的位置，**不是安全的"改分辨率"开关**。

### 框架自带的宽屏系统

引擎其实已经内建了一套可选的宽屏支持，位于：

- `SexyAppFramework/SexyAppBase.cpp`：`mWidths[] = { 800, 1066, 1280 }`、`mHeights[]`、
  `mWidescreenAware`（默认 `true`）、`mResolutionMode`（默认 `0` → 800×600）
- `SexyAppFramework/DDInterface.cpp`：
  `mWideScreenExtraWidth = mWidth - gSexyAppBase->mWidth; mWideScreenOffsetX = extra / 2`

**设计意图**：`gSexyAppBase->mWidth/mHeight` 保持 800×600 作为"设计基准"，
DDInterface 的 `mWidth/mHeight` 取实际分辨率，多出来的部分记录在
`mWideScreenOffsetX/Y` 里，所有 UI 通过 `+ mWideScreenOffsetX` 平移。

**要启用宽屏，正确做法是走 `mResolutionMode`，而不是直接改 `LawnApp` 的
`mWidth/mHeight`** —— 后者会同时改掉"设计基准"，使 DDInterface 算出的 extra 变成 0，
整套机制失效（上游 issue #55 就是这么来的）。

### 缩放过滤

工程**没有**调用 `SDL_SetDefaultTextureScaleMode`，SDL3 渲染器默认是
`SDL_SCALEMODE_LINEAR`。当窗口被放大或全屏时，整幅画面会被双线性放大，
像素风会变糊。逐贴图的模式在 `SDL3Image.cpp` / `SDL3Font.cpp` 里设置：

```cpp
SDL_SetTextureScaleMode(tex, pixelart ? SDL_SCALEMODE_PIXELART
                       : blend ? SDL_SCALEMODE_LINEAR : SDL_SCALEMODE_NEAREST);
```

想让整体更接近原版的硬边像素，可在创建渲染器后加：

```cpp
SDL_SetDefaultTextureScaleMode(mSDLRenderer, SDL_SCALEMODE_NEAREST);
```

## 3. 资源系统（PAK）

### 加载

`SexyAppBase::Init()` 中按顺序挂载：

```cpp
#ifdef _ALLOW_RESOURCE_PACKS
if (GetFileAttributesExA("resourcepack.pak", ...) != 0)
    gPakInterface->AddPakFile(_S("resourcepack.pak"));
#endif
// 之后还有 main.pak / dependency.pak 等
```

### 读取路径

界面代码读文件最终都走到 `p_fopen`（`PakLib/PakInterface.h`）：

```cpp
static PFILE* p_fopen(const char* theFileName, const char* theAccess) {
    if (GetPakPtr() != NULL)
        return (*gPakInterfaceP)->FOpen(theFileName, theAccess);
    ... // 无 pak 时直接 fopen
}
```

`PakInterface::FOpen`（`PakLib/PakInterface.cpp:194`）的行为：

1. 若访问模式是 `r` / `rb` / `rt` → 把路径转成**全大写**后在 pak 索引里查找；
2. 命中 → 返回指向 pak 内存的 `PFILE`；
3. **未命中 → 回退到真实文件系统 `fopen`**。

> 第 3 步很关键：它意味着"pak 里没有、但磁盘上有"的文件（例如存档）能被正常读取。

### 写入路径

写入用 `sexyfopen`（在 `Common.h` 里就是 `fopen` / `_wfopen`），**完全不经过 pak**。
所以 `SexyAppBase::WriteBytesToFile` 与 `ReadBufferFromFile` 用的是两套底层
（`fopen` 写、`p_fopen` 读），依赖上面的回退才能对称工作。

### 覆盖优先级（高 → 低）

```
resourcepack/     ← 资源包，可整体替换美术
extension/        ← 工程自带的扩展资源（assets/extension/）
dependency/       ← 依赖资源
────────────────
main.pak / dependency.pak 内，或磁盘上的裸文件
```

`assets/extension/` 当前含 `images/map.png` 和 `properties/resources.xml`。
新增资源需要 `properties/resources.xml` 里的 `SetDefaults` 路径以 `extension\` 开头。

## 4. 存档系统

### 位置

根目录由 `savedata.ini` 决定（本仓库新增，详见 [04-存档配置](04-存档配置.md)）。
默认：`%APPDATA%\PopCap Games\PlantsVsZombies\`。

存档都在根目录的 `userdata\` 子目录下。

### 文件

| 文件 | 写入者 | 内容 |
|---|---|---|
| `userdata\users.dat` | `ProfileMgr::Save` | 档案列表（名称、id、进度摘要） |
| `userdata\user<id>.dat` | `PlayerInfo::SaveDetails` | 单个玩家的详情（关卡、金币、成就等） |
| `userdata\game<profile>_<mode>.dat` | `Board::SaveGame` | 进行中的关卡 |
| `userdata\game<profile>_<mode>_replay_<level>.dat` | 同上 | 冒险模式的关卡重放存档 |

路径构造集中在：

- `Lawn/System/ProfileMgr.cpp` — `GetAppDataFolder() + "userdata/users.dat"`
- `Lawn/System/PlayerInfo.cpp` — `GetAppDataFolder() + StrFormat("userdata/user%d.dat", mId)`
- `Lawn/LawnCommon.cpp` — `GetSavedGameName(GameMode, profileId[, level])`

### 注册表

游戏设置和"当前用户"存在注册表：

```
HKCU\Software\<mRegKey>
    CurUser, MusicVolume, SfxVolume, ScreenMode, PreferredX/Y, ...
```

`mRegKey` 来自 properties 的 `RegistryKey` 项（`SexyAppBase.cpp:1963`），
**实测为 `SteamPopCap\PlantsVsZombies`**。`LawnApp::WriteToRegistry()`
在退出时写 `CurUser` 并调用 `mPlayerInfo->SaveDetails()`。

> 存档本体在文件系统，注册表只存设置与"上次是谁"。排查"存档丢失"时
> **先看 `userdata\` 目录是否存在**，再看注册表。

### 启动时的档案选择

`LawnApp::Init()`（约 2202 行）：

```cpp
mProfileMgr->Load();                       // 读 users.dat，失败则档案表为空
if (mPlayerInfo == nullptr && RegistryReadString("CurUser", &theUser)) {
    mPlayerInfo = mProfileMgr->GetProfile(aCurUser);   // 名字匹配
}
if (mPlayerInfo == nullptr)
    mPlayerInfo = mProfileMgr->GetAnyProfile();        // 退而求其次
```

两者都拿不到 → 显示新建用户对话框 → `AddProfile` → **`mProfileMgr->Save()`**。

## 6. 源文件编码约定

### 规则

- **全库统一 UTF-8。**
- 所有 8 个配置都带 `/source-charset:utf-8`（在 `SexyAppBase.vcxproj` 的
  `ClCompile → AdditionalOptions`）。
- 新增或修改源文件请**保存为 UTF-8**。含非 ASCII 字符的文件（注释里的中文、
  字符串字面量里的中文）**建议带 BOM**：带 BOM 时 MSVC 会优先按 BOM 判断编码，
  不受系统代码页影响，最稳。
- **不要依赖系统 ANSI 代码页**。这一点对中文 Windows 尤其重要。

### 为什么必须这样

本工程历史上混用三种编码，且没有指定源码字符集，于是编译结果依赖**编译机器的
ANSI 代码页**：

- 在英文/西欧系统（CP1252）上能编过；
- 在中文系统（**CP936**）上会出现 `C2001 常量中有换行符`、
  `C1057 宏扩展中遇到意外的文件结束`、`C3873`、`C3688` 等错误而**完全无法编译**。

具体案例与修法见 [变更记录 01 · 修复源码编码导致的编译失败](changes/2026-10-07-01-source-encoding.md)。

### 自查

找出仍然不是合法 UTF-8 的源文件：

```powershell
$utf8 = New-Object System.Text.UTF8Encoding($false, $true)
Get-ChildItem -Recurse -Include *.c,*.cpp,*.h,*.hpp,*.inc |
  Where-Object { $_.FullName -notmatch '\\\.git\\' } |
  Where-Object {
    try { [void]$utf8.GetString([IO.File]::ReadAllBytes($_.FullName)); $false }
    catch { $true }
  } | Select-Object -ExpandProperty FullName
```

### 已经踩过的坑

- `LawnApp.cpp` / `EditWidget.cpp` 曾因此编译失败（已修）。
- `include/dx8sdk/*.h` 是第三方 DirectX 8 头文件，原本是 CP1252，**已转 UTF-8**。
  升级这个第三方目录时记得重复转换。
- `LawnApp.cpp:1900` 有一句硬编码中文 `_S("买下这个物品？")`（原文如此），
  注意别在搜索替换时破坏它。

## 8. 命令行入口

`LawnApp` 通过命令行参数切换运行模式（`LawnApp::Init()` 里判断）：

| 参数 | 模式 | 说明 |
|---|---|---|
| （无） | 正常游戏 | |
| `-particleeditor` | 粒子编辑器 | 标题栏显示 "Particle Editor v0.1 by @inliothixie" |
| `-screensaver` | 屏保 | 强制全屏，标题 "Zen Garden" |
| （预览屏保） | — | 标题 "Zen Garden Preview"，窗口化 |

`assets/` 里有两个启动脚本：

```bat
:: ParticleEditor.bat
cd ..\..\Output
"PlantsVsZombies.exe" -particleeditor
```

> ⚠️ 这两个 `.bat` 里的 `..\..\Output` 是**旧的输出路径**，
> 当前输出目录是 `build\<Configuration>_<Platform>\bin\`。脚本实际已失效，
> 需要手改成正确路径（或直接带参数运行 exe）。

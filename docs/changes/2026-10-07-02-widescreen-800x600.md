| 项 | 值 |

| 提交 | `3b8caf7` — Restore the original 800x600 rendering |
| 类型 | 修复（渲染 / 观感） |
| 影响 | 渲染 |
| 涉及文件 | `LawnApp.cpp` |

## 背景与症状

运行后画面与原版明显不同，并且**能看到"可见区之外"的区域** —— 棋盘两侧多出
本不该出现的内容。窗口也不是原版的 4:3。

上游已有人报同样的问题：
[issue #55 "Game resolution is broken"](https://github.com/InLiothixi/stabledecompile/issues/55)
（2025-10-18 提交，**至今未关闭、零评论**）。报告人贴的截图窗口为 1068×752，
描述与现象一致，并提到另一个反编译工程 PvZ-Quality-of-the-Lawn-Decompile
没有这个问题。

## 根因

### 硬编码的宽屏开关

`LawnApp::Init()` 里有一行**无条件**的宏定义（没有 `#ifndef` 保护，
任何外部开关都覆盖不了它）：

```cpp
#define _WIDE_SCREEN
#ifdef _ULTRA_WIDESCREEN
    mWidth = 1280;  mHeight = 720;
    mDDInterface->mWideScreenOffsetX = 240;
    mDDInterface->mWideScreenOffsetY = 60;
#elif defined(_WIDE_SCREEN)
    mWidth = 1066;  mHeight = 600;
    mDDInterface->mWideScreenOffsetX = 133;
#endif
gBoardBounds = Rect{ 0, 0, mWidth, mHeight };
```

原版是 **800×600**（`BOARD_WIDTH` / `BOARD_HEIGHT`，见 `GameConstants.h`），
而且 `LawnApp` 的构造函数本来就正确设成 800×600 —— 这里被强制改成 **1066×600**。

算术对得上：

```
1066 - 800 = 266
266 / 2   = 133     ← 正是那个硬编码的偏移量
```

画面左右各被撑出 133px，而**美术资源只覆盖 800×600**，
于是 266px 的"画面之外"被露了出来。

### 它同时架空了框架自带的宽屏系统

引擎其实已经内建了一套规范的可选宽屏支持：

| 位置 | 内容 |
|---|---|
| `SexyAppFramework/SexyAppBase.cpp` | `mWidths[] = { 800, 1066, 1280 }`、`mHeights[]`、`mWidescreenAware = true`、`mResolutionMode = 0` |
| `SexyAppFramework/DDInterface.cpp` | `mWideScreenExtraWidth = mWidth - gSexyAppBase->mWidth; mWideScreenOffsetX = extra / 2` |

**设计意图**：`gSexyAppBase->mWidth` 保持 800×600 作为**设计基准**，
由 `mResolutionMode`（默认 0 → `mWidths[0]` = 800）选择实际分辨率，
多出来的宽度记录在 `mWideScreenOffsetX/Y` 里，UI 通过 `+ mWideScreenOffsetX` 平移。

**但 LawnApp 在 DDInterface 之前就把 `mWidth` 改成了 1066**，
于是 DDInterface 算出 `mWideScreenExtraWidth = 1066 - 1066 = 0` ——
通用机制失效，最后只有那个硬编码的 133 生效。

### 旁证：这个功能没做完

- `GameConstants.h` 里 `WIDE_BOARD_WIDTH = 800`，与 `BOARD_WIDTH` **完全相同** ——
  名为"宽屏棋盘宽度"，实际根本没加宽；
- `_WIDE_SCREEN` 分支只设了 `offsetX`，**漏设 `offsetY`**
  （对比 `_ULTRA_WIDESCREEN` 两个都设了）。

## 改动

`LawnApp.cpp`：把那一行 `#define` 注释掉，并写清原因与 issue 链接。

```cpp
// Widescreen canvas override.
// NOTE: Hardcoding this forced the game to 1066x600 with a 133px horizontal offset
// instead of the original 800x600. ...
// Upstream report: https://github.com/InLiothixi/stabledecompile/issues/55
// Commented out to restore the original 800x600 rendering.
//#define _WIDE_SCREEN
#ifdef _ULTRA_WIDESCREEN
...
```

**为什么注释掉就够**：两个分支分别由 `#ifdef _ULTRA_WIDESCREEN` 和
`#elif defined(_WIDE_SCREEN)` 保护，而这两个宏在全库**再无任何 `#define`**，
所以两个分支都变成死代码 → `mWidth` / `mHeight` 回落到构造函数的
`BOARD_WIDTH` / `BOARD_HEIGHT` = **800×600**，
`mWideScreenOffsetX/Y` 回落到 `DDInterface` 的 0。

沿用了项目自己在 `GameConstants.h` 里 `//#define XXX` 的开关惯例，
保留了代码结构和 `_ULTRA_WIDESCREEN` 备用。

### 没有采用的方案

- **直接把 `mWidth` 改成 800**：只改一处，但保留了"LawnApp 覆盖设计基准"这个
  错误模式，以后别人再开宽屏还会踩同一个坑。
- **改成 `mResolutionMode = 1`**：会让游戏以 1066×600 启动，问题依旧。

## 验证

宏确实不再被定义（只应看到 `#ifdef` / `#elif` 的引用）：

```powershell
Select-String -Path LawnApp.cpp -Pattern '^\s*#\s*define\s+(_WIDE_SCREEN|_ULTRA_WIDESCREEN)'
# 期望：无输出
```

运行后应看到：

1. 窗口是 **800×600（4:3）**；
2. 左右两侧多出来的区域消失；
3. 棋盘 / 按钮位置与原版一致。

ReleaseGOTY|x64 与 DebugGOTY|x64 重新构建均 **0 error**。

> 本次未做像素级截图比对，最终以目视确认收尾。

## 回退

```powershell
git revert 3b8caf7
```

回退后恢复到 1066×600 的硬编码宽屏。

**若想正确启用宽屏**，应改走框架自己的 `mResolutionMode` + `mWidths[]` 机制
（配合把 `WIDE_BOARD_WIDTH` 真正加宽、补齐 `mWideScreenOffsetY`），
而**不是**恢复这个硬编码 —— 那正是 issue #55 的成因。
